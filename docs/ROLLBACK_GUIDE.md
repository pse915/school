# 롤백

## 코드

- 배포 전 기존 원본 커밋, 1단계 커밋, Secrets 사본을 안전하게 보관한다.
- 이 ZIP의 checkpoint bundle에는 원본→1단계→2단계 로컬 개발 이력이 있다. CHECKPOINT.txt의 커밋을 확인한다.
- 전체 적용 후 문제가 생기면 GitHub에서 직전 검증 커밋으로 되돌리고 **해당 커밋의 frontend/dist도 함께** 복원한다.
- 시험감독 엔진/스키마는 바꾸지 않았으므로 되돌리기 과정에서 시험감독 데이터 초기화나 마이그레이션을 하지 않는다.

## 데이터

- 코드 롤백은 데이터 롤백이 아니다. 5A/5B/6 확장 저장소의 이력/버전을 삭제하지 않는다.
- 날짜별 변경 취소는 신규 사유·버전을 남기는 복구 절차를 사용한다. 이후 변경이 존재하면 기존 확정본을 무조건 덮어쓰지 않는다.
- donor의 cancel_confirmed는 최신 변경에 대해서만 가능하며 기본적으로 배포본은 자동으로 되돌리지 않는다. 복구 변경을 검증·승인·확정한 뒤 새 배포를 수행한다.
- 전체 저장소 복원은 확장 payload, 활성 slot, revision, checksum, ScriptProperties를 같이 확인한다. 문서 복제만으로 활성 포인터 복원이 되었다고 간주하지 않는다.
- 기존 Google Sheets 시간표/시험감독과 신규 확장 저장소는 분리되어 있다. 둘을 서로 다른 시점으로 복구하면 충돌할 수 있으므로 쓰기를 중단하고 세 저장소의 버전과 실제 일정부터 대조한다.

실 운영 복구 훈련은 미실행이다. 복제본에서 절차를 검증한 다음 운영에 적용한다.
