# 게이트웨이 없는 직접 시트 연결

학교 표시명 설정은 `docs/SCHOOL_BRANDING_GUIDE.md` 참조. 기존 데이터 학교 ID와 별개이며 `[school] name`으로 설정한다.

## 가장 간단한 설정
기존 Streamlit Secrets의 기본 시트·관리자·시험감독·`[gcp_service_account]` 내용은 그대로 둡니다. `[school_sheets]`가 이미 있으면 그 섹션 안에서 수정하고, 없으면 아래를 추가합니다. 기존 School_id 값이 있다면 유지하세요. 같은 TOML 섹션을 중복 작성하지 마세요.

```toml
[school_sheets]
Gogyohak_sheet = "https://docs.google.com/spreadsheets/d/확장문서ID/edit"
```

이것으로 수강신청·이동반·결보강·학기 시간표의 **공유 확장 저장소**를 설정합니다. 학기 시간표만 이름을 쓰고 싶다면 `Semester_sheet` 하나만 입력해도 같습니다. Apps Script 배포·게이트웨이 주소·공유 키는 필요하지 않습니다.

1. 비공개 확장 Google 스프레드시트를 준비합니다.
2. 기존 Secrets의 `gcp_service_account.client_email` 이메일을 이 문서의 **편집자**로 공유합니다.
3. 위 주소를 넣고 Streamlit 앱을 재시작합니다.
4. 기존 관리자 계정으로 로그인하고 수강신청/학기 시간표 메뉴에서 자료를 저장합니다.

네 가지 키 Gogyohak_sheet/Idongban_sheet/Operations_sheet/Semester_sheet를 모두 표시하려면 예제 TOML을 복사합니다. 빈 항목은 입력된 문서를 공유합니다. 현재 데이터 계약상 서로 다른 문서로 업무를 분리하지 않습니다. 기본 시간표·시험감독 문서를 대체하지 않습니다.
School_id가 없고 기존 credit.school_id도 없으면 문서ID에서 안정적인 학교ID를 생성합니다. 기존 데이터가 있는 환경은 기존 School_id를 유지해야 합니다. URL을 다른 문서로 바꾸는 것은 데이터 이전이 아닙니다.

## 저장 방식과 보존
기존 서비스 계정과 gspread 클라이언트를 재사용합니다. `_DipleExt_srb_credit_v1_...` 전용 탭을 자동 생성하고 영구 데이터를 Google Sheets에 저장합니다. 탭의 메타데이터·체크섬과 base64 snapshot은 사람이 편집하는 표가 아닙니다. 임시 SQLite 파일을 영구 저장소로 쓰지 않으며 계산 중 메모리 SQLite만 사용합니다. 전용 탭을 수동 편집/삭제하지 마세요.
원본 시간표/시험감독 worksheet, 관리자 비밀번호·계정, 저장 계약은 바꾸지 않습니다. 확장 저장본에는 학생 개인정보가 있으므로 문서를 공개하지 마세요.

## 동시 저장 지원 범위
**동일한 단일 Streamlit 프로세스의 여러 사용자 세션**은 문서별 공유 lock으로 직렬화합니다. 작업본 revision, 확정 request key 및 서비스의 기존 검증을 유지합니다. snapshot 메타와 본문은 한 번의 Sheets batchUpdate로 함께 기록합니다. 응답 유실은 저장 ID와 본문을 재조회하며, 확인되지 않으면 해당 문서의 모든 세션에서 쓰기를 차단합니다. 이전 요청의 저장 ID와 내용이 확인되면 자동 해제하며, 단순히 이전 revision을 읽었다고 차단을 해제하지 않습니다. 응답 유실 후 늦게 완료되는 요청이 있을 수 있기 때문입니다. 요청이 끝내 저장되지 않았다면 진행 중 요청이 모두 종료되었음을 관리자가 확인한 뒤 앱을 재시작해야 합니다. 재시작은 진행 중 요청의 부재를 자동 증명하지 않습니다. 최근 읽기는 2초간 공유 캐시를 사용하지만 쓰기 전후에는 원격본을 직접 확인합니다.
여러 서버/복제 앱/게이트웨이가 같은 문서에 쓰는 **분산 CAS는 지원하지 않습니다**. Sheets API는 조건부 revision 쓰기를 제공하지 않으므로 사전 재조회만으로 이를 해결했다고 주장하지 않습니다. 하나의 앱 프로세스만 이 전용 탭에 쓰게 해야 합니다. 알려진 WEB_CONCURRENCY/STREAMLIT_WORKERS>1 설정은 쓰기 연결을 거부합니다. 별도 호스트의 writer 존재를 자동 증명/감지하지 못합니다. 이 운영 조건을 만족하지 못하면 직접 방식의 확정·적용을 사용하지 말고 기존 게이트웨이를 유지하세요.
Google API 요청 쿼터가 있으며 다수 학생 동시 제출이나 큰 학교 전체 부하는 미검증입니다. 오류 시 성공으로 표시하지 않습니다. 12MiB base64 snapshot 한도는 기존 게이트웨이와 같은 보호 한도이며 처리 성능 보증이 아닙니다.

## 기존 게이트웨이를 쓰고 있다면
기존 [credit] 또는 Gateway_url 설정은 계속 지원하며 자동으로 직접 방식으로 바꾸지 않습니다. 기존 연결 정보가 있으면 게이트웨이를 우선 유지합니다. 데이터가 없는 문서를 직접 방식으로 명시하려면 `Storage_mode = "direct"`를 추가할 수 있습니다.
문서에 기존 DIPLE5A_ 게이트웨이 저장 탭이 있으면 **빈 직접 저장소로 전환하지 않고 차단**합니다. gateway snapshot과 ScriptProperties 포인터를 포함한 데이터 이전 검증 없이 기존 운영 데이터를 자동 이동/초기화하지 않습니다. 두 방식을 같은 문서에서 병렬 운영하지 마세요.

## 검증의 한계
직접 어댑터의 생성/저장/재조회, 응답 유실, 동시 세션, corruption, 기존 데이터 보호 및 통합 흐름은 Google API 모의 전송으로 검증합니다. 실제 Google 문서 인증정보가 없어 실 Google 저장은 미검증입니다. 실제 사용 전 복제 문서에서 읽기/쓰기/재조회와 할당량을 확인하세요.
