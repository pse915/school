# 1단계 확장 저장소 및 권한

현재는 운영 연결 전 검증본이다. 실 Google 복제본 검증은 수행하지 않았다.

1. 운영 문서의 **복제본 또는 별도 테스트 Google 스프레드시트**를 만든다. 기존 시험감독 Apps Script를 수정하지 않는다.
2. 그 테스트 문서에 새로 바인딩한 Apps Script 프로젝트에서 `integrations/enrollment/Code.gs`를 넣는다.
3. 스크립트 속성에 `DIPLE_SHARED_KEY`를 32자 이상 안전한 난수로 지정한다.
4. 해당 스크립트를 실행 주체 소유자, 접근 누구나인 웹앱으로 배포한다. 모든 읽기/쓰기는 서버 HMAC 검증 후 허용되며, 서명 키는 브라우저나 저장소에 공개하지 않는다.
5. **테스트용 Streamlit 배포**의 기존 Secrets를 유지하고 다음 블록만 추가한다. 관리자 비밀번호나 계정을 추가하지 않는다.

```toml
[credit]
school_id = "school-test-001"
academic_year = 2026
gateway_url = "https://script.google.com/macros/s/실제_검증용_배포_ID/exec"
gateway_shared_key = "스크립트_속성과_동일한_32자_이상_난수"
```

6. namespace는 `srb_credit_v1_` + school_id SHA-256 앞 24자이며 45자 제한을 충족한다. 다른 학교는 별도 school_id와 저장 경계를 사용한다.
7. 합성 명렬 2명으로 회차·과목 등록→학생 활성화·제출→마감/검토→신청 확정→자동분반→교사/교실/요일교시 지정→편성 확정 순으로 검증한다.
8. 테스트 앱을 재시작한 뒤 결과/이력/버전을 재조회한다. 두 세션 동시 제출, 오래된 화면 수정, 응답 유실, 게이트웨이 키 오류, 쿼터 오류, 백업 복구를 검증한다.
9. 복제본 검증 전 운영 설정/문서를 바꾸지 않는다. 기존 시간표·시험감독 저장 설정과 워크시트는 이 작업 대상이 아니다.

## 저장 형식과 동시성

문서의 확장 워크시트 `DIPLE5A_<namespace>_A/B`에 base64 SQL 스냅샷을 분할 기록한다. 활성 slot, revision, checksum은 ScriptProperties에 있다. 전체 SQL에 학생·신청·감사로그·분반 버전이 포함된다. 따라서 문서만 복제해서는 ScriptProperties까지 복구되지 않는다. 테스트 후 **SQL payload 및 활성 포인터를 함께 보존하는 백업 절차**를 마련해야 한다.

서버에서 메모리 SQLite로 트랜잭션을 수행하고, gateway가 LockService 아래 revision CAS 후 커밋한다. 로컬 디스크 SQLite를 운영 저장소로 사용하지 않는다. CAS 충돌은 덮어쓰지 않고 실패한다. 리비전 충돌 후 최신 데이터를 조회하여 재시도한다. 게이트웨이 미설정/통신 오류 시 신규 영구 저장을 허용하지 않는다.

전체 스냅샷 직렬화는 소규모 학교 검증용 방식이며, 대량 동시 수강신청 운영을 보증하지 않는다. 실부하 및 응답 유실 복구 시험이 완료되기 전 공개 운영 금지.

## 권한

- 관리자: 기존 srbmaster 로그인과 `can_manage_ids()` 판정 재사용. 학생 비밀번호 원문 조회 불가.
- 학생: 명렬 등록 시 발급한 1회 코드로 활성화, Argon2id 비밀번호 인증. 본인 신청과 확정 시간표만 조회.
- 서비스 키: Streamlit 서버와 서명 게이트웨이 사이에만 존재. 기존 Sheets/시험감독 Secrets는 유지.
