# 학교명 설정 및 일반 배포 안내

기존 Streamlit Secrets를 유지하고 아래 섹션을 추가하세요. 이미 `[school]`이 있으면 그 안의 값을 수정하며 중복 섹션을 추가하지 않습니다.

```toml
[school]
name = "우리학교 이름"
```

Secrets 저장 후 앱을 재시작하면 로그인 화면, 상단 학교명, 하단 표시, 기존 시간표의 새 Excel/인쇄물, 수강신청 기초자료와 새 학기 작업본에 반영됩니다. 설정이 없거나 빈 이름이면 `학교`로 표시합니다. Secrets 파일 자체가 없어도 기본 로그인 화면은 열립니다.

학교명은 일반 텍스트 100자 이하입니다. HTML 태그와 줄바꿈은 허용하지 않습니다. 기존 최상위 `SCHOOL_NAME` 값도 호환하지만 위 `[school] name` 설정을 우선합니다.

## 나이스 학사일정
학교명과 API 키만 입력합니다. 학교정보 API에서 교육청·학교코드를 자동 조회하고 학사일정 API에 전달합니다.

```toml
[school]
name = "우리학교의 정확한 이름"
neis_api_key = "기존 나이스 API 키"
```

기존 최상위 NEIS_API_KEY도 지원합니다. 교육청·학교코드 설정은 읽지 않으며 예전 placeholder 값이 남아 있어도 무시합니다. 자세한 키 위치와 동명이교 구분은 NEIS_NAME_ONLY_GUIDE.md 참조.

## 기존 시트·계정 보존
학교명 변경은 표시 및 나이스 조회 설정입니다. `school_sheets` 문서 주소·학교 ID·Google 서비스 계정·관리자 계정/비밀번호·시험감독 저장소를 자동 변경하거나 이전하지 않습니다. 다른 학교에 배포할 때는 해당 학교의 시트와 기존 연결 설정도 따로 준비하세요.
기존 확정본/신청 snapshot/감사 이력의 학교명은 불변 기록으로 보존합니다. 표시명 변경만으로 과거 확정 데이터를 다시 쓰지 않습니다.

## 개발 및 배포 범위
실행 소스의 특정 학교 표시명과 고정 나이스 fallback을 제거했습니다. 기존 보관용 Git bundle과 과거 테스트/보존 문서는 당시 원본의 이력이며, 과거 Git 기록까지 삭제한 익명화 작업은 아닙니다. 운영 진입점은 계속 `timetable_app2.py`입니다. 배포 시 보관용 bundle을 실행할 필요는 없습니다.
동작 검증과 변경 목록은 `SCHOOL_BRANDING_RESULTS.md` 및 `SCHOOL_BRANDING_CHANGED_FILES.md`를 확인하세요. 운영 사이트·문서에는 직접 배포/쓰기를 하지 않았습니다.
