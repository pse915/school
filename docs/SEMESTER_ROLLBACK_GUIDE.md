# 복구 절차

## 적용 전
작업본과 후보는 운영본이 아니다. 이전 후보(parent) 선택/undo 또는 기존 확정본을 그대로 유지한다. 실패·취소·입력 변경 결과를 확정하지 않는다.

## 적용 실패/응답 유실
같은 repo 내 pointer+Phase6 base 등록은 단일 transaction이므로 부분 SQL 실패 시 rollback된다(실제 trigger 실패 테스트 통과). 응답 유실 시 적용 포인터를 재조회하고 같은 final/date를 재시도한다. 동일 final 재시도는 추가 버전을 만들지 않는다. 다른 관리자 revision이면 최신 상태로 다시 검토한다. 최종본 저장이 성공하고 적용이 실패한 경우 불변 final은 보존되며 재시도 가능하다.
원격 Google 게이트웨이 실제 장애/응답 유실은 이번 환경에서 검증하지 못했다. 임의로 원격 snapshot을 덮어쓰지 않는다.

## 이전 기본본 재적용
확정·적용·출력에서 이전 final ID와 현재/미래 적용일을 선택하고 동일 전체검증/미래변경 차단을 통과시킨다. 과거 적용일·배포본은 수정하지 않는다. 새 pointer 및 Phase6 base로 전환되며 이전 final은 삭제되지 않는다. 기존 날짜별 변경이 충돌하면 먼저 검토해야 하므로 복구도 차단될 수 있다.

## 코드 롤백
신규 코드만 되돌릴 경우 Phase2 commit 952d3f8 또는 동봉된 phase2 checkpoint를 별도 브랜치에 복구한다. 확장 데이터/감독 데이터는 초기화하지 않는다. 코드 롤백만으로 이미 적용한 새 기본본이 Phase2 legacy reader에 보이는 것은 아니므로, 먼저 적용 상태를 검토하고 계획된 전환/포인터 비활성화 절차를 백업된 복제본에서 검증한다. 원본 Sheets로 자동 역기록하는 기능은 제공하지 않는다.
