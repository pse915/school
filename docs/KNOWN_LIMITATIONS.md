# 알려진 제한과 운영 전 확인

## 미검증

1. **실 Google Sheets 복제본 저장·재조회**: 테스트 문서/배포 URL/서명 키 미제공. 모의 서명·CAS·다중 쓰기 충돌 시험은 통과했지만 실 Google 시험을 대신하지 않는다.
2. 운영 pse915 계정과 운영 URL의 실제 로그인/쓰기/배포는 수행하지 않았다. 원본 인증을 유지하고 합성 계정으로 시험했다.
3. 실 iPad/Safari/Android 기기, 대량 동시접속, Google 쿼터/Apps Script 실행제한, 장시간 장애/실백업 복구는 미검증이다.

## 부분 완료 또는 설계 경계

- 신규 운영 문서 안의 날짜별 다중 변경/관련 날짜 배포는 CAS로 원자적이다. **기존 시간표·시험감독·신규 운영이라는 서로 다른 저장소 전체를 묶은 분산 트랜잭션은 구현하지 않았다.** 저장 전 양방향 충돌검사는 있지만 별도 구버전 앱/GAS/시트 직접편집과의 동시 쓰기까지 원자적으로 보장하지 않는다. 운영 전 쓰기 경로를 단일 버전으로 통일하고 복제본에서 경합을 검증해야 한다.
- 기존 날짜별 시간표가 운영 변경 이후 바뀐 것으로 감지되면 source fingerprint 불일치로 신규 확정/배포를 제한한다. 기존 revision>0 날짜에 대해 상충한 두 시스템 변경을 자동 병합하는 UI는 제공하지 않는다. 사유·이력을 유지하는 별도 조정이 필요하다.
- 기존 시간표에서 이미 있는 선택수업과 Phase 5B의 동일 선택수업을 자동으로 추정하여 삭제하지 않는다. 중복/충돌하면 기준 등록을 거부한다. 학교 데이터의 선택수업 표기/ID를 명시적으로 정리해야 한다.
- 교사·과목·학급은 기존 데이터에 매핑한다. Phase 5B 교사 ID가 기존 교사명과 다르면 operations.teacher_map을 설정해야 한다. 임의 누락으로 충돌을 숨기지 않는다.
- 교실은 기존 시간표의 교실 값 및 확정 분반 교실에서 수집한다. 별도 전교 교실 마스터 관리 UI는 없다. room_capacities 설정이 없으면 명시된 기본 수용값(999)을 사용하므로 실제 수용인원 검증에는 학교값 입력이 필요하다.
- Phase 5B 자동배정은 가상 구획을 계산하며 실제 요일·교시는 관리자가 지정한다. Phase 6으로 가져올 때 실제 학생/교사/교실 전체를 합쳐 검증한다. 실제 요일·교시 전교 최적화 기능을 새로 만들지는 않았다.
- 학교별 대강 제한은 담당교과, 교과 외 허용, 교사별 가능 과목/요일/부재일, 일일 상한, 기존 교사 가용교시·시간강사 기간을 지원한다. 임의의 모든 학교 규칙을 표현하는 범용 규칙 편집기는 없다.
- 신규 학기 중 운영의 교실/학사행사/연쇄교환 등 전체 편집은 기존 관리자에게 제공하고, 일반교사는 본인 조회·이동 요청/이력만 제공한다. 학생은 본인 배포 일정만 조회한다.
- 확장 저장소는 전체 SQL payload를 전송하므로 학교 규모와 이력 증가에 따른 성능 제한이 있다. 게이트웨이 base64 12MiB 제한과 Sheets/Apps Script 쿼터를 고려해 실부하 검증이 필요하다. Streamlit 임시 디스크 SQLite는 운영 저장소로 사용하지 않는다.
- 응답 유실 후 저장 여부는 재조회해야 한다. 브라우저 timeout이 서버의 저장 취소를 뜻하지 않는다. 저장 상태를 확인하지 않고 재실행하지 않는다.
- 새로고침 시 기존 인증 정책대로 재로그인한다. 새로고침 후 자동 인증 유지 기능을 새로 추가하지 않았다.

최종 결과는 **로컬 통합 및 실제 브라우저 검증 완료 / 실 Google 운영 검증 미완료**인 배포 준비본이다. 무조건적인 공개 운영 보증이나 모든 저장소의 동시 쓰기 안전성 보증으로 해석하지 않는다.
