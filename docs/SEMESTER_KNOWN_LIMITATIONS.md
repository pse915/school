# 알려진 제한과 미검증 범위

현재 직접 연결: `docs/DIRECT_SHEETS_GUIDE.md` 참조. 기존 서비스 계정과 확장 시트 주소만으로 연결하며 게이트웨이는 선택 사항이다. 아래 gateway 설명은 기존 방식의 계약으로 보존한다.

- 실제 Google 복제본 자격정보가 없으므로 저장·동시성·재조회는 로컬 repo/CAS 모의 계약에서만 검증했다. 운영 쓰기/배포는 하지 않았다. 운영 안전 검증 완료로 보고하지 않는다.
- 월~금만 지원한다. 토요일·주기별 A/B주·학기 중 임의 시정표 변경은 미지원. 교사 계약 시작/종료가 학기를 완전히 덮지 않으면 사전검증에서 보완을 요구한다.
- 시간대 충돌은 실제 분 단위 구간으로 검사한다. 이동 부담 가중치는 일일 교실 수 proxy이며 물리 거리/이동 소요시간 최적화가 아니다.
- Phase5B 연결은 실제 학생 ID를 보존하지만 일반학급 학생명렬까지 완전해야 공통수업 간 실학생 검증이 완전하다. class.size는 전체 인원으로 명시하고 개별 학생 roster 누락을 관리자가 점검해야 한다. 알려지지 않은 학생을 자동 추정하지 않는다.
- 미래 Phase6 변경/확정/배포 및 구 legacy 변경이 있으면 적용을 제한한다. 충돌 비교/차단은 구현했으나 자동 병합·재기반화 작업 UI는 미구현이다. 차단을 제거하려고 기존 요청을 자동 삭제하지 않는다.
- 원본 모의 수업교환(use_test) 데이터 경로는 그대로 유지한다. 새 학기 적용본을 원본 sandbox로 자동 복제하지 않는다. 학기 시간표 실험은 불변 후보의 분기/편집으로 수행한다.
- 새 학기 적용 시 원본 조회는 Phase6 published day를 읽는다. 구 Sheets 자체는 새 기본본으로 바뀌지 않는다. 기존 감독 엔진의 호환 일정 어댑터를 사용하며 다른 시험감독 엔진은 연결하지 않았다.
- background job은 세션 내 thread다. 새로고침/서버재시작 후 재개 불가. 원격 lease가 만료되면 재실행 가능하며 늦은 결과는 폐기한다. 다중 후보 중 일부 저장 후 나머지 저장 실패 시 이미 저장된 후보는 남을 수 있다.
- 입력 저장은 CAS로 중복 append를 막지만 모든 CRUD에 영구 request receipt를 추가한 것은 아니다. 확정은 영구 request key, 적용은 동일 final/date 멱등 재조회, 편집은 preview token/불변 후보를 사용한다. 이 범위를 벗어난 네트워크 중복 생성은 최신 목록을 확인해야 한다.
- 원본 실제 운영 계정 로그인과 물리 모바일/Safari는 미검증. 실제 진입점 E2E는 로그인 렌더까지, authenticated 전 과정은 동일 브리지 fixture다. 네트워크 오류/중복/지연의 모든 조합을 매 모달에서 전수 검증하지 않았다.
- 합성 18학급/450회차 FEASIBLE은 실제 학교 전체·제약 조합의 최적성/성능 보증이 아니다. 제한시간은 탐색시간이며 전체 wall은 모델 생성만큼 더 길 수 있다.
- 기존 원격 저장소 전체의 분산 원자성은 제공하지 않는다. 코드 롤백과 데이터 적용 롤백은 별도다. 해당 범위는 배포 가이드의 검증 전까지 운영 적용을 제한해야 한다.
